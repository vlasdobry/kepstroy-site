# Генераторы с установкой в Крыму

Локальная реализация от 04.09.2026. URL: `/uslugi/generatory/`.

## Архитектура

Одна общекрымская страница в разделе услуг. Входящие ссылки: главная, `/krym/`, 12 городских хабов и страницы газоснабжения/подключения электричества. Шаблон `generators/city-index-template.html` также обновлён. Отдельные городские страницы генераторов не создавались. В будущем солнечная услуга может получить собственную страницу без изменения этого URL.

Статический HTML + `css/generatory.css` + `js/generatory.js`; shared CSS/JS и backend не изменены. Page-local JS синхронизирует доступность мобильного меню, удерживает клавиатурный фокус, поддерживает Escape и prefers-reduced-motion.

## Оффер и источники

Пользователь подтвердил установку присланного оборудования по всему Крыму. На странице: резерв для дома, бизнеса, промышленности; примеры WL50/WL150/WL350/WL1000-CNG; Jenbacher 616 как пример индивидуального промышленного проекта. Фото подписаны как примеры оборудования, не как завершённые работы КэпСтрой.

Не публикуем валютный прайс поставщика как стоимость под ключ, неподтверждённые сроки/наличие/гарантии, солнечную услугу и обещания бесперебойности. Не смешиваем описание Pulsar G12KBN с фотографиями Westinghouse WGen10500TFc. Последний по [официальной документации](https://westinghouse.com/products/wgen10500tfc-tri-fuel-with-co-sensor) имеет 120/240 В и 60 Гц, поэтому не выставлен как готовый комплект для местной сети.

Оригиналы сохранены вне webroot, в корне проекта `docs/assets/from-andrey/power-systems-2026-08/raw/`. Там же реестр и подробные выводы. Полное конверсионное ТЗ: `docs/plans/2026-09-04-generators-page-design.md` в корне проекта (рядом с репозиторием `kepstroy-site`, не внутри него).

Три WebP-производных занимают суммарно 275 492 байта. Они находятся внутри `html/images/generatory/` и попадут в существующий Docker-образ без изменения Dockerfile. Исходные PDF/видео в образ не входят.

## Заявки и аналитика

POST `/submit`: `phone`, необязательные `name` и `message` (до 1000 символов), `service=Генераторы с установкой`, `form_source=kepstroy`, `consent`, пустые `website`/`company`. Атрибуцию добавляет существующий `tracking.js`. Используются текущие `phone_click`/`form_submit`; источник услуги виден в Telegram. Новые цели или рекламные кампании не создавались.

## Проверки

```powershell
python -m unittest discover -s tests -v
python scripts/validate.py
node --check html/js/generatory.js
node --test --test-isolation=none form-handler/test/*.test.js
```

Обычный `npm test --prefix form-handler` в этом sandbox завершался `spawn EPERM`: запрет дочерних процессов тестового раннера. Те же 7 тестов проходят с `--test-isolation=none`; зависимости и production-код ради этого не менялись.

Для браузерной проверки нужен доступный Playwright в Node module path и локальный сервер:

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory html
# В другом терминале с настроенным NODE_PATH:
node tests/generators-browser.cjs http://127.0.0.1:8765
```

Тест допускает только 127.0.0.1 и перехватывает `/submit`, поэтому не отправляет реальные заявки. Проверяет ширины 360/390/768/900/1024/1280/1440, отсутствие горизонтального overflow, видимую навигацию, клавиатуру, FAQ, обязательные поля, сохранение данных при ошибке, успешный переход, UTM/yclid/client_id, загрузку фото и входящие ссылки. Скриншоты в игнорируемой папке `html/screenshots/generators/`.

Перед публичным запуском нужна отдельная команда на merge/push/deploy. Lighthouse и живую доставку Telegram этой локальной проверкой не подтверждаем.
