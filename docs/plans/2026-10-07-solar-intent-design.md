# Выбор солнечного предложения: согласованный дизайн

Пользователь 07.10 после просмотра аудита попросил «вноси правки нужные». Основание — `docs/marketing/kepstroy-cleanup-and-conversion-2026-10-07.md` в корне рабочего проекта. Пакет: исправление выбора панелей, текста формы, рекламного сообщения двух намерений, быстрой ссылки и маршрутизации исключений узлов системы. Бюджет и стратегия прежние; реальные доказательства не придумываются.

Выбран минимальный подход: один существующий подбор и одна форма с явной передачей намерения через `data-solar-intent`. Отдельные страницы/формы увеличили бы объём и дублирование; исправление только скрытого текста не устранило бы несоответствие кнопок и селектов. Карточки, товарные CTA и ссылки блока заказов меняют сценарий и синхронизируют подбор, текст формы, кнопку и скрытое сообщение. Панели устанавливают задачу покупки; переход обратно к системе заменяет задачу покупки на консультацию. Остальные данные пользователя сохраняются. На прямом открытии `#panel` выбираются панели, на `#calculator` — система по умолчанию; последующие якорные переходы не сбрасывают выбранные ответы без явного выбора сценария. Существующие цели и серверный контракт формы сохраняются.

Рекламные группы «Панели — без гео» и «Электростанции и монтаж — без гео» получают разные наборы заголовков/текстов по проверенным ключам. Географические группы с двумя намерениями сохраняют общий оффер. У всех наборов быстрых ссылок заменить старое обещание калькулятора количества на «Подбор системы». Три компонента (`аккумулятор`, `инвертор`, `кабель`) перенести с кампании в товарную группу, чтобы запросы полноценной системы с этими узлами могли участвовать в показах. Прочие исключения, включая уже применённую чистку, сохранить. Не объявлять изменение доказанным ростом обращений; контроль нового компонентного спроса требуется при следующей проверке запросов.

Проверка: регрессионный браузерный тест сначала красный на старом JS; затем все 13 URL на мобильном и desktop, покупка/подключение/монтаж, прямой `#panel`, переключения, сохранение данных и фактический FormData перед перехваченным POST. Ни один тест не отправляет заявку наружу. Проверить генератор, Python-контракты, JS runtime, CI и живой сайт после деплоя. Рекламные изменения: свежий MCP снимок, локальная проверка длины, точных ID, синтаксиса и ключей; запись, readback, статус модерации. Небезопасные большие ID не преобразовывать в JavaScript Number.
