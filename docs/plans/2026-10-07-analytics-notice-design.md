# Уведомление аналитики: доступность звонка и измерение закрытия

Пользователь согласовал 07.10: добавить события показа и закрытия уведомления и разместить его над нижними кнопками. Согласование получено в разговоре после предложения конкретного варианта. Клиентское сообщение не отправлять.

Общий analytics-consent.js сохраняет немедленный запуск Метрики и прежнюю отметку ознакомления. При первом отображении за загрузку страницы отправляет analytics_notice_shown; при реальном закрытии кнопкой — analytics_notice_dismissed, один раз. Сохранённая отметка или legacy consent не создают событий скрытого уведомления. Эти диагностические цели не добавляются в приоритетные цели Директа.

Общий загрузчик измеряет высоту существующих фиксированных нижних панелей (.solar-mobile-cta, .sticky-phone) и их отступ снизу. Уведомление размещается выше них с зазором, высота перепроверяется при resize и изменении размеров панели. На страницах без фиксированной панели остаётся обычный нижний отступ. Удаляется конфликтующий солнечный CSS override, источник размещения становится общим. Стандартные браузеры без ResizeObserver используют resize и начальное измерение.

Все публичные страницы и шаблоны получают новую версию общего загрузчика. Безопасность форм, доставка в MAX, рекламные бюджеты и приоритетные цели не меняются. Проверка отправок форм выполняется локально без клиентских сообщений.

Для доли закрытий использовать визиты с закрытием / визиты с показом за один и тот же период и сегмент. Количество достижений событий может включать повторные страницы и не равно числу людей. Ретроспективных данных нет.

Проверки: новые runtime-тесты сначала падают, потом проходят; браузерная матрица ширин 320/360/390/768 и desktop проверяет обычный клик без force и отсутствие пересечения. Метрика перехвачена локально, /submit блокируется. После публикации — отдельная QA-кампания, события сверяются в MCP-отчёте.
