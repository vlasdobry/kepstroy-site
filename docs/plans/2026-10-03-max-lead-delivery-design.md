# Доставка заявок в закрытую группу MAX

Пользователь согласовал независимую отправку форм сайта в Telegram и закрытую группу MAX. Группа создана, Андрей добавлен, бот проходит модерацию. Этот этап — подготовка кода и конфигурации без публикации и без реальных заявок.

## Решение

Прямой вызов официального MAX Bot API из существующего Node.js form-handler. Альтернативы: отдельный сервис/конструктор (лишняя зависимость) или пересылка из Telegram (не устраняет зависимость от Telegram). Для одного исходящего метода достаточно уже установленного node-fetch; официальный SDK рассмотрен, но подключение его инфраструктуры и очередного пакета здесь не требуется.

Оба настроенных канала запускаются параллельно. Ответ /submit успешен после первого подтверждения доставки; ошибки всех каналов дают существующий 500 с телефоном. Каждый HTTP ограничен 8 секундами; в MAX очередь максимум 10 ожидающих, ожидание до 8 секунд с удалением просроченной задачи, активная доставка всей заявки до 20 секунд. Конкурентная заявка резервирует телефон и IP до результата, чтобы параллельные POST не обходили cooldown. Нет автоматических повторов POST из-за риска дублирования при неизвестном исходе. Исходящее сообщение MAX содержит весь существующий текст заявки, а длинный текст делится на части до 4000 символов с учётом лимита два сообщения в секунду. Полная доставка канала подтверждается только после всех частей.

MAX настраивается парой MAX_BOT_TOKEN / MAX_CHAT_ID. Отсутствие обоих отключает канал; неполная/невалидная конфигурация считается ошибкой запуска. Telegram остаётся доступен в прежнем режиме, разрешён также MAX-only. Polling Telegram запускается только при наличии его конфигурации.

Токен MAX передаётся в Authorization, chat_id сохраняется строкой (int64 без потери точности). Сертификат Минцифры доверяется только отдельным HTTPS-agent MAX, стандартные CA сохраняются, проверка TLS обязательна. Журналы доставки содержат только название канала, результат и безопасный тип ошибки, без секретов, тела API и данных клиента.

Первая версия MAX поддерживает текст и кнопку звонка. Обратные callback-статусы Telegram не переносятся в MAX: их синхронизация требует отдельного хранилища и не входит в согласованную подготовку.

## Подключение после модерации

Токен сохранить в секретах, добавить бота в группу, получить chat_id через GET /updates событие bot_added (GET /chats удалён). Подготовленный скрипт не публикует входящие тексты. После заполнения обеих переменных — read-only проверка /me и членства бота, затем явная тестовая отправка без персональных данных и production smoke реальной доставки. До этого задача полной интеграции остаётся незавершённой.

## Проверки

Тесты реального /submit через локальный HTTP и перехват только внешнего fetch: оба успешны, один недоступен, один завис, оба недоступны, MAX отключён, MAX-only, антиспам и CI-bypass. Отдельно проверяются запрос MAX, HTTP/API-ошибки, размер/части сообщений, сертификат и конфигурация. Старые тесты форм и frontend/runtime сохраняются.
